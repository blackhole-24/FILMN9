■ 프롬프트 본문 (이 아래부터 Claude Design 에 붙여넣기)

당신은 네이버·구글·오라클 출신 40년차 CTO이자 컴퓨터공학과 교수입니다.
아래 서비스의 **시스템 아키텍처 다이어그램을 "로컬 호스트 버전 단 1장"** 으로,
컴퓨터공학 교과서 수준의 정석으로 그려주세요. (excalidraw / 손그림 톤)

★★ 이번 그림의 1순위 목표 ★★
"사용자가 클릭하면 → 어떤 경로로 데이터를 가져와서 → 어떤 기능 화면을
사용자에게 보여주는가" 라는 **전체 데이터 흐름(요청→응답)** 을, 그 누구도
한눈에 이해할 수 있게 **굵고 명확한 화살표**로 표현하는 것입니다.
→ 화살표가 이 그림의 주인공입니다. 박스는 단순하게, 화살표는 강조해서.

★★ 절대 원칙: 간결함 ★★
- 큰 틀의 박스 6개만 둡니다. 박스 "안"은 핵심 그룹만 적고, 세부 항목을
  잘게 쪼개 나열하지 마세요. (예: 재무정보 안에 Sankey·BS·IS·주주·공시를
  따로따로 박스로 만들지 말 것. "재무정보" 한 덩어리로 묶을 것.)
- AWS·VPC·로드밸런서 같은 클라우드 인프라는 그리지 마세요. 로컬 1장만.

────────────────────────────────────────────────────────────
■ 큰 박스 6개 (왼쪽 → 오른쪽 흐름 순서로 배치)
────────────────────────────────────────────────────────────

① USER (사용자)  ─ 가장 왼쪽
   - "일반 투자자" 1종만. (학생/기관 등 세분화 금지)
   - 한 줄 설명: "기업 분석, 이제 5분 만에 — KOSPI/KOSDAQ 약 2,600개 상장사"

② FRONTEND (화면)  ─ Next.js 16 · React 19 · 로컬 Port 3000
   박스 안에는 "사용자가 보는 화면" 만 큰 틀로:
   - 홈: 검색 · 산업(업종)별 탐색 · 모닝 마켓시그널 위젯 · 밸류 요약
   - 종목 상세화면 (탭 3개) ← 이 그림의 중심:
       · [Tab1] 기업개요 파트
       · [Tab2] 밸류에이션 파트
       · [Tab3] AI 챗봇
   - 관리자 페이지 (/admin, 탭 4개)  ← 아래 ⑥ 참고
   ※ Tab1·Tab2 의 "안에 뭐가 들었는지"는 아래 [기능 그룹] 박스로 별도 표현.

③ FASTAPI (API 라우터 계층)  ─ "요청 받는 입구"
   - FastAPI · Python 3.11 · 로컬 Port 8090
   - 역할 한 줄: 프론트의 요청(주소/URL)을 받아 알맞은 기능으로 넘기는 "교통정리".
   - 큰 그룹만: 종목 종합조회 / 재무·주가 / 산업분류 / 밸류에이션 /
     모닝시그널 / 관리자(admin). (개별 엔드포인트 나열 금지)

④ BACKEND (서비스·비즈니스 로직 계층)  ─ "실제 일하는 곳"
   - 역할 한 줄: DB에서 데이터를 꺼내 가공·집계해 화면용으로 만들어 돌려줌.
   - 여기서 기능을 **두 파트**로 크게 나눠 표현 (이게 이 그림의 핵심 구조):

     ┌─────────────────── [A] 기업개요 파트 ───────────────────┐
     │  기능 3가지로만 나눔:                                     │
     │   1) 히스토리 브리핑  (LLM이 만든 기업 스토리)            │
     │   2) 주가차트        (일봉 OHLCV·거래량)                 │
     │   3) 재무정보  ★한 덩어리로 묶기★                        │
     │        = 손익흐름도(Sankey) · 재무상태표(B/S) ·          │
     │          손익계산서(I/S) · 주주구성 · 기업개요 ·         │
     │          전자공시(DART)  ← 이 6개를 "재무정보" 안에       │
     │          작은 글씨로만 묶어 표기 (따로 박스 만들지 말 것) │
     └──────────────────────────────────────────────────────────┘

     ┌─────────────────── [B] 밸류에이션 파트 ──────────────────┐
     │  큰 틀로만:                                               │
     │   DCF(현금흐름할인) 적정주가 · WACC(가중평균자본비용)     │
     │   · 멀티플/피어비교 · 민감도  ← 큰 묶음으로만 표기        │
     │   (산업 대표 20종 사전계산, 점진 확대)                    │
     └──────────────────────────────────────────────────────────┘

   - AI 챗봇은 별도 마이크로서비스로 분리(아래 ⑤). Backend 안에 넣지 말 것.

   ★ AI RAG 챗봇 = 별도 작은 서비스 박스 (Backend 옆 아래)
     - FastAPI · 로컬 Port 8800 (메인 8090 과 분리된 마이크로서비스)
     - BGE-M3 임베딩 + 리랭커 + gpt-5-mini, SSE 스트리밍
     - Frontend Tab3 ↔ 8800,  8800 ↔ 벡터DB(ChromaDB) 로 연결.

⑤ DATABASE (데이터 저장소)  ─ "데이터가 쌓여 있는 곳" · 큰 박스 1개 안에 4종
   각 DB가 "어느 화면 데이터를 담는지" 한 줄씩만:
   - 관계형 DB (SQLite filmn9.db) : 기업개요·재무·주가·주주·공시·밸류요약
   - 문서 DB (MongoDB Atlas)      : 히스토리 브리핑
   - 벡터 DB (ChromaDB)           : 사업보고서 임베딩(약 377만 청크) → 챗봇 검색
   - 파일 저장소 (로컬 파일)       : Sankey HTML(약 2,600개)·밸류 JSON·계열사 SVG

⑥ EXTERNAL API (외부 데이터 원천)  ─ 오른쪽 위, Backend 로 유입
   - DART(공시·재무 원문) · OpenAI(gpt-5-mini) · yfinance/KRX(주가) ·
     ECOS/KOFIA(금리) · 네이버(뉴스·환율) · WICS(78개 업종 분류)
   - 한 줄: "대부분 사전 배치 수집, 주가 현재가만 실시간 조회".

────────────────────────────────────────────────────────────
■ 관리자 페이지 (⑥ 신규 반영 — 꼭 포함)  ─ Frontend /admin, 탭 4개
────────────────────────────────────────────────────────────
Frontend 박스 안(또는 옆)에 "관리자 페이지" 작은 박스로 두고, 탭 4개를 표기:
   ① 기업개요 운영      (서비스 생존·DB통계·종목 커버리지·신선도 모니터링)
   ② 밸류·챗봇 관리자   (데이터 기준일·출처·테스트환경·AI 하네스)
   ③ 기업개요 검증      (내부 정합성·DART 원문 대조 — NO-MOCK 검증)
   ④ 밸류·챗봇 테스트   (헬스·밸류 QA·챗봇 QA·체크리스트)
→ 관리자 페이지도 같은 FastAPI(/api/admin/*)·DB를 조회한다는 화살표 1~2개로 연결.

────────────────────────────────────────────────────────────
■ 화살표 (★이 그림의 주인공 — 가장 강조)
────────────────────────────────────────────────────────────
다음 흐름을 **굵은 화살표 + 번호 ❶❷❸❹❺** 로 명확히:
   ❶ USER  →  FRONTEND        : 검색·클릭 (요청 시작)
   ❷ FRONTEND  →  FASTAPI      : API 요청(URL 호출)
   ❸ FASTAPI  →  BACKEND       : 알맞은 기능으로 라우팅
   ❹ BACKEND  →  DATABASE      : 데이터 조회
   ❺ DATABASE → BACKEND → FASTAPI → FRONTEND → USER : 응답(화면 표시)
- 응답 화살표(❺)는 요청과 구분되게 색/방향을 다르게(예: 요청=파랑 실선,
  응답=초록 실선). 왕복이 한눈에 보이게.
- EXTERNAL API → BACKEND : 별색(주황 점선)으로 "외부에서 데이터 유입(배치)".
- Tab3 ↔ 8800 챗봇 ↔ ChromaDB : 챗봇 전용 흐름을 짧게.
- 좌하단에 작은 [범례] 박스: 요청/응답/외부유입/배치 화살표 색 의미.

────────────────────────────────────────────────────────────
■ 교과서 정석 요소 (간결 유지하되 빠지면 안 되는 것)
────────────────────────────────────────────────────────────
- 계층 분리(3-tier: 화면 / API / 데이터) 가 시각적으로 드러날 것.
- 마이크로서비스 분리: 메인 API(8090) vs AI 챗봇(8800) 가 별개 서비스임.
- "실시간 vs 배치" 구분: 주가 현재가=실시간, 나머지(밸류·브리핑·Sankey·임베딩)
  =사전 배치 계산. 한 줄 주석으로.
- 로컬 런타임 한 줄: conda(FINSIGHT_env/chatbot_env) · GPU RTX 4060 ·
  Windows 작업 스케줄러(주가 매 거래일 16:00 자동 동기화).
- NO-MOCK 원칙 작게 1줄: "근거 없는 값은 표시 안 함 → 없으면 '데이터 없음'".
