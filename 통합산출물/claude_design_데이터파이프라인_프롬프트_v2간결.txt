■ 프롬프트 본문 (이 아래부터 Claude Design 에 붙여넣기)

당신은 네이버·구글·오라클 출신 40년차 데이터 아키텍트이자 컴퓨터공학과
교수입니다. 아래 서비스의 **데이터 흐름도(Data Pipeline)** 를 데이터
엔지니어링 교과서 수준의 정석으로, 간결하게 1장 그려주세요.
(excalidraw / 손그림 톤, 가로형 왼쪽→오른쪽 흐름)

※ 이것은 "시스템 구성도"가 아니라 "데이터의 여정"입니다. 박스는 서버가 아니라
  **데이터의 상태(원천 → 수집 → 저장 → 가공 → 서빙 → 소비)** 입니다.

★★ 이번 그림의 1순위 목표 ★★
"외부에서 들어온 원천 데이터 한 덩어리가, 어떤 가공을 거쳐, 어느 저장소에
쌓이고, 결국 사용자 화면의 어떤 기능이 되어 나오는가" 라는 **데이터 계보
(lineage)** 를, 그 누구도 한눈에 추적할 수 있게 **굵고 명확한 화살표**로
표현하는 것입니다. → 화살표(흐름)가 이 그림의 주인공입니다.

★★ 절대 원칙: 간결함 ★★
- 단계(6개)별로 큰 박스만. 세부를 잘게 쪼개지 말 것.
- 특히 "재무정보"는 한 덩어리로 묶기(Sankey·BS·IS·주주·기업개요·공시를
  따로따로 그리지 말 것).

────────────────────────────────────────────────────────────
■ 단계 6개 (왼쪽 → 오른쪽)
────────────────────────────────────────────────────────────

① 원천 (SOURCE)  ─ 가장 왼쪽 · "데이터가 태어나는 곳"
   - DART(사업보고서·공시 원문) · yfinance/KRX(주가) · ECOS/KOFIA(금리)
   - 네이버(뉴스·환율) · WICS(78개 업종) · OpenAI(LLM 답변·보조)
   - 한 줄: 모든 데이터의 공통 열쇠 = 6자리 "종목코드(stock_code)".

② 수집 (INGESTION)  ─ "긁어와서 정리하는 작업(Job)"
   - DART 수집·재무 파서(XBRL → 표 형태로 정규화)
   - 주가 일배치: ohlcv_daily_sync.py (매 거래일 16:00 자동, 갭만 UPSERT)
   - 기업개요/주주/경영인/공시 수집
   - 한 줄: 대부분 "배치(미리 모아둠)", 주가 현재가만 "실시간 조회".

③ 가공 (TRANSFORM / 사전계산)  ─ ★이 파이프라인의 심장★
   "사용자 요청 시 즉석 계산이 아니라, 미리 만들어 저장(precompute)" 임을 강조.
   기능을 **두 파트**로 묶어 표현:

     ┌──────────── [A] 기업개요 파트 가공 ────────────┐
     │ 1) 히스토리 브리핑 생성(LLM)                    │
     │     generate_briefs → evaluate(4단계 채점)      │
     │     → merge_best → MongoDB 적재                 │
     │ 2) 주가차트 데이터 정리 (일봉 OHLCV)            │
     │ 3) 재무정보  ★한 덩어리★                        │
     │     = 재무 정규화 + 건전성 신호등 +             │
     │       손익흐름도(Sankey, build_sankey_v3 약     │
     │       2,600개 사전생성) + 계열사 SVG            │
     └────────────────────────────────────────────────┘

     ┌──────────── [B] 밸류에이션 파트 가공 ───────────┐
     │ DCF 엔진 v8:                                     │
     │   run_valuation_auto(피어 자동선정+DCF)          │
     │   → export_poc(결과 JSON) → load_valuation_      │
     │     summary(요약 적재)                           │
     │ 산출: 적정주가·WACC·멀티플 (산업대표 20종)       │
     └─────────────────────────────────────────────────┘

     ┌──────────── [C] AI 챗봇용 가공 ─────────────────┐
     │ 사업보고서 청킹 → BGE-M3 임베딩(1024차원)        │
     │   → ChromaDB 적재 (약 377만 청크)                │
     └─────────────────────────────────────────────────┘

④ 저장 (SERVING STORE)  ─ "가공 결과가 쌓이는 4개 저장소"
   - 관계형 DB(SQLite filmn9.db) : 기업개요·재무·주가·주주·공시·밸류요약
   - 문서 DB(MongoDB)            : 히스토리 브리핑
   - 벡터 DB(ChromaDB)           : 사업보고서 임베딩(약 377만 청크)
   - 파일 저장소                 : Sankey HTML·밸류 JSON·계열사 SVG

⑤ 서빙 (API)  ─ "저장소에서 꺼내 화면용으로 내보냄"
   - 메인 API: FastAPI Port 8090 (조회·집계·서빙)
   - AI 챗봇: 별도 Port 8800 (질의 → ChromaDB 검색 → 리랭크 →
     gpt-5-mini 생성 → SSE 스트리밍)
   - 한 줄: 모닝 위젯 15분 캐시 + 기동 prewarm.

⑥ 소비 (CONSUMPTION)  ─ 가장 오른쪽
   - Frontend(Next.js, 3000) → 일반 투자자 화면
     (홈 · 산업탐색 · 종목상세 3탭 · 관리자 4탭)

────────────────────────────────────────────────────────────
■ 화살표 (★주인공 — 데이터 계보가 추적되게)
────────────────────────────────────────────────────────────
- 왼쪽→오른쪽 **굵은 화살표**로 ①→②→③→④→⑤→⑥ 큰 흐름.
- 단계 사이마다 "무엇이 흐르는지" 짧은 라벨(예: ②→③ "원문 XBRL",
  ③→④ "정규화된 표/JSON/벡터", ⑤→⑥ "화면용 응답").
- 예시 계보 1줄을 굵게 강조(데모용):
  "DART 사업보고서 → 임베딩 → ChromaDB → 챗봇(8800) → Tab3 AI 챗봇 답변".
- 좌하단 [범례] 박스: 배치(회색 실선) / 실시간(빨강 점선) 구분.

────────────────────────────────────────────────────────────
■ 교과서 정석 요소 (간결 유지하되 빠지면 안 되는 것)
────────────────────────────────────────────────────────────
- [배치 vs 실시간] 상단 가로 레인 2개: 대부분 배치(사전계산), 주가 현재가만
  실시간. 각 흐름이 어느 레인인지 색/점선으로 구분.
- [스케줄러] 주가=매 거래일 16:00(Windows 작업 스케줄러)가 ②를 트리거하는
  화살표. 밸류·브리핑·Sankey·임베딩=수동/주기 배치.
- [품질 게이트] healthcheck_full.py 전수검증(약 2,600종목) + NO-MOCK
  (근거 없는 값 금지, 없으면 "데이터 없음") 을 작은 게이트 박스로.
- [멱등성] 주가·재무 적재는 "갭만 보충하는 UPSERT(여러 번 돌려도 안전)".
- [관리자 검증 연계] 관리자 페이지(검증 탭)가 ④ 저장소를 DART 원문과
  대조한다는 점선 화살표 1개.
