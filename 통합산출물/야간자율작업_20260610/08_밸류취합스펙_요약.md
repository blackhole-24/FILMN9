# 밸류에이션 취합 스펙 — 핵심 요약 (미독 문서 확인 완료)

> 원문: `docs/PM_참고문서/밸류에이션_취합_스펙_및_합의.txt` (2026-06-02 작성)
> 확인: 2026-06-10 야간 자율작업 · 밸류 3,000 전수취합(#1·#2) 실행 전 필독 스펙

## 1. 취합 = "폴더 복사만으로 끝" (서버 재시작 불필요)
- 종목별 폴더를 `data/valuation_results/{종목코드}_{종목명}/` 에 넣으면 화면 자동 전환.
- 엔드포인트: `GET /api/valuation/{code}`. 폴더 없으면 `is_mock:true` → 프론트 "준비중".
- 폴더명 규칙: 코드+"_" 로 시작(뒤 이름 자유). 같은 코드 여러 개면 최신 수정시각 우선.
- 현재 실데이터 동작: 090430 아모레 · 009150 삼성전기 · 035420 NAVER (3종 = 정답 템플릿).

## 2. ★핵심 스키마 불일치 (취합의 병목)
- 밸류에이션 파트 엔진 `run_valuation.py` 산출 = **합본 1파일**(`valuation_<날짜>.json`, 한글 키, Streamlit용).
- 그러나 백엔드가 읽는 형식 = **6개 분리 파일**(영문 snake_case 키). 키·구조·단위가 다름.
- repo에 "합본→6파일 변환" 스크립트 **없음** → 데모 3종목 6파일은 밸류에이션 파트이 수동/비공개로 생성.
- ⇒ **합의 필요**: 밸류에이션 파트이 그 export 방법을 공유 → 전 종목에 돌리면 취합 완료.
  (대안: 우리가 변환기 작성. 단 단위·키 손실 위험 → 밸류에이션 파트 원본 export가 정확)

## 3. 6개 파일 (데모 090430 기준 = 정답 템플릿)
| 파일 | 핵심 내용 |
|---|---|
| `dcf_result.json` | 적정주가·current_price·upside·EV·WACC·시나리오(Bear/Base/Bull)·검증 |
| `fcff_result.json` | FCFF 5년+TV·매출/EBIT/세금/CAPEX·할인계수·PV (단위 십억원) |
| `wacc_result.json` | Rf·ERP·베타·Ke·Kd·가중치·피어 자본구조·하마다 |
| `multiples_result.json` | 멀티플별 피어중위·implied 주가·vs현재가 |
| `peer_beta_result.json` | 피어 베타(raw/adj·R²) — [0]=본인 |
| `uncertainty_result.json` | 민감도 매트릭스(WACC×g)·토네이도 |
> 단위 주의: 금액 = **billion(십억원)**, 주가 = **원**.

## 4. 3,000 전수취합 실행 메모 (#1·#2 연계)
- 입력 데이터 준비됨: 밸류 ChromaDB(31GB)·valuation.db(77MB)·results(2,352개) 배치 완료(6/10).
- 실행 경로: `run_valuation_auto.py --ticker {코드}` → `export_poc.py`(6파일 변환) → `data/valuation_results/` 배치.
- ⚠️ 종목당 DART XBRL·ECOS·RAG 조회로 무거움. OpenAI 비용 여부 = 실행 전 확인 필요(피어/정성 LLM).
- NO-MOCK: 우리가 밸류 숫자 임의 생성 금지. 밸류에이션 파트 산출 실데이터만 반영.

## 5. 미해결 = 낮에 밸류에이션 파트과
- [요청] 합본→6파일 export 스크립트(또는 방법) 공유 → 전 종목 일괄 변환.
- current_price는 산출 시점 스냅샷 → 화면은 realtime 우선([01 검증리포트] 참고).
