# current_price 정합성 검증 리포트 (NO-MOCK)

> 작성: 2026-06-10 야간 자율작업 · 검증 대상: `valuation_summary` 20종 · 데이터 원천: filmn9.db + realtime API(yfinance)
> 결론 한 줄: **밸류 화면의 `current_price`는 6/1 산출 시점 값(과거)이라 20종 중 16종이 실제 현재가와 5%↑ 괴리. 화면 현재가를 realtime/ohlcv로 교체해야 함.**

## 1. 검증 방법
- `valuation_summary.current_price`(밸류 산출 시점 가격) vs **ohlcv 최신 종가**(6/10) vs **realtime API**(yfinance, 6/10 14:59) 3자 비교.
- 괴리율 = (밸류 current_price − ohlcv 종가) / ohlcv 종가 × 100.

## 2. 핵심 발견
1. **realtime API = ohlcv 최신 종가 (100% 일치)** — 교차검증 5종 모두 동일:
   | 종목 | realtime(6/10) | ohlcv(6/10) | 일치 |
   |---|---|---|---|
   | 삼성전기(009150) | 1,805,000 | 1,805,000 | ✅ |
   | SK하이닉스(000660) | 2,048,000 | 2,048,000 | ✅ |
   | NAVER(035420) | 227,000 | 227,000 | ✅ |
   | SKT(017670) | 105,700 | 105,700 | ✅ |
   | 현대모비스(012330) | 570,000 | 570,000 | ✅ |
   → **진짜 현재가 = ohlcv/realtime**. valuation의 current_price만 다름.

2. **valuation `current_price`는 산출 시점(as_of_date) 고정값** — 분포: **6/1(17종)·6/4(2종)·6/3(1종)**. 즉 6/10 기준 **6~9일 묵은 값**.

3. **20종 중 16종이 5%↑ 괴리** (대부분 밸류가 과대). 이 값으로 `upside_pct`(상승여력)를 계산해 화면에 쓰면 상승여력이 왜곡됨.

## 4. 권장 해결책 (NO-MOCK 준수)
- **(A) 화면 현재가를 realtime/ohlcv로 교체** — 밸류 화면·랭킹의 "현재가"는 `valuation_summary.current_price`(과거값) 대신 **`/api/realtime/{code}` 또는 ohlcv 최신 종가**를 사용. (이미 종목 헤더는 realtime 사용 중 → 밸류 탭/요약만 정렬)
- **(B) 상승여력 재계산** — `upside_pct = (fair_price − 현재가) / 현재가`를 **최신 현재가 기준으로 재산출**. 적정가(`fair_price`)는 산출물 그대로 유지.
- **(C) 표기 정직화** — valuation의 current_price를 굳이 보여줘야 하면 **"산출시점(6/1) 기준가"로 라벨링**하고 현재가와 분리 표시.
- ⚠️ **임의 수정 금지(NO-MOCK)**: DB의 current_price 값을 손으로 바꾸지 말 것. 화면 로직에서 "현재가는 realtime, 적정가는 산출물"로 출처를 분리하는 게 정답.
