# FINSIGHT 개발 프로세스 — 워터폴 + 에자일 (역설계)

문서버전 v1.0 · 2026-06-05

> 실제로는 화면(HTML) 중심 vibe coding으로 빠르게 구현했으나, 발표를 위해
> **전통적 프로세스로 역구성**한다. 두 관점(워터폴 설계 / 에자일 실행)을 병기.

---

## A. 워터폴 관점 (설계 단계의 논리적 순서)
1. **목적 정의** — 개인 투자자의 5분 종합 분석.
2. **사용자·요구사항** — 페르소나(일반투자자) → SRS(FR/NFR, NO-MOCK).
3. **프로세스 설계** — 데이터 수집→가공→저장→서빙→소비 파이프라인.
4. **아키텍처 설계** — 5계층 + 외부API + 인프라, 챗봇 MSA 분리.
5. **데이터 모델(ERD)** — company_info 허브 16테이블.
6. **구현** — 백엔드(FastAPI)/프론트(Next.js)/챗봇(RAG).
7. **통합·검증** — 전수검수(healthcheck), 신뢰도 검증.
8. **DB·배포** — RDB/문서/벡터/객체, AWS.
9. **운영·QA** — 관리자 페이지, 일배치, 비용 관리.

→ 산출물: 헌장·요구사항·페르소나·WBS·아키텍처·ERD·데이터흐름·관리자 설계.

## B. 에자일 관점 (실제 스프린트 실행)
| 스프린트 | 기간(개념) | 핵심 산출 |
|---|---|---|
| S1 데이터 기반 | ~ | DART 수집·재무 파싱·주가 적재·DB 스키마 |
| S2 화면 골격 | ~ | 종목 상세 3탭·검색·산업 탐색 |
| S3 분석 자산 | ~ | Sankey 생성·히스토리브리핑·임베딩 |
| S4 통합·밸류·AI | ~6/2 | 밸류 탭·모닝·계열사·AI탭 RAG 연결 |
| S5 신뢰성·취합 | 6/3~6/5 | 전수검수·동결·취합·리브랜딩·아키텍처/ERD/UI 산출물 |
| S6 운영·발표 | 6/5~6/20 | 관리자 페이지·신뢰도 검증·AWS 배포·최종 발표 |

- 의식(Ceremony): 데일리 점검(업무일지), 스프린트 종료 회고(retro 문서),
  백로그 정렬(MoSCoW), 동결(freeze) 후 데모.
- 변경 관리: 구두 추가업무는 WBS v6로 정식 편입(추적성 확보).

## C. 두 관점의 결합
- 워터폴로 "왜/무엇을"의 논리를 보증하고, 에자일로 "어떻게 빠르게"를 실행.
- 발표는 워터폴 순서로 스토리텔링, 근거는 에자일 산출물(실제 화면/코드)로 제시.
