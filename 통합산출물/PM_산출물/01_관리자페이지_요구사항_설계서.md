# FINSIGHT 관리자 페이지 — 요구사항 · 설계서

문서버전 v1.0 · 2026-06-05 · 작성: PM(자동) · 상태: 설계(구현 전)

---

## 1. 개요 · 목적
FINSIGHT는 KOSPI·KOSDAQ 약 2,600개 상장사를 대상으로 한 AI 기업분석·가치평가 플랫폼이다.
데이터가 DART·시장·LLM 등 다양한 원천에서 배치/실시간으로 유입되므로, **운영 상태를
한눈에 보고(모니터링) + 데이터의 신뢰도를 정량 검증**하는 내부 관리자 페이지가 필요하다.

본 페이지의 두 핵심 가치:
- **운영 가시성**: 서버·DB·배치·캐시·커버리지·에러를 한 화면에서 점검하고 유지보수.
- **신뢰성 보증(NO-MOCK)**: 화면에 표시되는 모든 수치/문장이 원본(DART·DB·계산식)과
  일치하는지 샘플·전수 검증하고 오류율을 산출.

> 설계 원칙: **읽기 전용(Read-mostly) 모니터링 우선**, 위험한 쓰기 작업은 별도 확인.
> 기존 자산 재사용(히스토리브리핑 `evaluate.py` 4-Phase, `healthcheck_full.py`).

## 2. 사용자 · 권한
| 역할 | 설명 | 권한 |
|---|---|---|
| 운영자(Operator) | 서버/데이터 상태 점검·유지보수 | 탭1 전체 + 재적재 트리거 |
| 검증자(Validator) | 데이터 신뢰도 샘플/전수 검증 수행 | 탭2 전체 |
| 뷰어(Viewer) | 현황 열람만 | 읽기 전용 |

- 접근 제어: 관리자 전용 경로(`/admin`), 환경변수 기반 단순 토큰/베이직 인증(데모 단계),
  추후 AWS Cognito/IAM 연동.

## 3. 화면 구조 (2탭 + 부가 2영역)

```
/admin
 ├─ [탭1] 기본 관리자 — 개발/운영 모니터링
 ├─ [탭2] 신뢰도 검증 — 샘플/전수 정합성 검사
 ├─ (부가) 데이터 관리 — 사업보고서 갱신·재적재
 └─ (부가) AWS 비용 관리 — S3/RDS/EC2 사용량·요금
```

## 4. [탭1] 기본 관리자 — 개발/운영 모니터링

### 4.1 표시 영역(위젯)
1. **서비스 헬스**: 백엔드(8090 `/health`) · 프론트(3000) · 챗봇(8800) UP/DOWN, 응답시간.
2. **DB 현황**: 테이블별 행수 — company_info, financials, financial_detail, ohlcv(일봉),
   shareholders, executives, disclosures, valuation_summary 등 16종. 빈 테이블 경고.
3. **데이터 신선도**: 주가 OHLCV 최신 동기화 일자(16:00 배치 성공 여부),
   공시/재무=사업보고서 시즌, 밸류/Sankey/계열사=사전배치 최근 생성일.
4. **종목 커버리지**: 기준 종목수(2,580) 대비 — Sankey(~2,627), 밸류(20), 계열사(샘플 7),
   히스토리브리핑(~2,526) 보유율(%).
5. **검색·결과도출 작동확인**: 샘플 종목(예: 005930)으로 종합조회·재무·밸류·검색 API
   200/응답시간 자동 핑.
6. **캐시 상태**: 모닝 위젯 15분 캐시 hit/age, prewarm·자동갱신(14분) 동작 여부.
7. **에러/이상 로그**: 최근 5xx, NO-MOCK 위반 후보(빈값·mock 흔적) 카운트.
8. **유지보수 액션**(확인 후 실행): 모닝 캐시 강제 갱신, OHLCV 수동 동기화 트리거,
   Sankey 재생성 안내(`build_sankey_v3.py`).

### 4.2 데이터 소스/연계
- `healthcheck_full.py`(2,588×11 항목 전수검수) 결과를 요약 카드로.
- DB 직접 COUNT 쿼리(읽기 전용).
- 작업 스케줄러(OHLCV 16:00) 마지막 실행 로그(`data/ohlcv_sync_log.txt`).

### 4.3 API 설계(spec — 구현 시 backend/routers/admin.py)
| 메서드·경로 | 기능 |
|---|---|
| `GET /api/admin/health` | 3개 서버 상태·응답시간 |
| `GET /api/admin/db-stats` | 테이블별 행수·빈테이블 |
| `GET /api/admin/freshness` | 배치별 최신 동기화 시각 |
| `GET /api/admin/coverage` | 기준종목 대비 파트별 보유율 |
| `GET /api/admin/smoke` | 샘플 종목 API 핑 결과 |
| `POST /api/admin/cache/refresh` | 모닝 캐시 강제 갱신(확인 필요) |

## 5. [탭2] 신뢰도 검증 — 정합성 검사

### 5.1 목적
"화면에 보이는 값이 원본과 같은가?"를 **파트별로 샘플/전수 검증**하여 오류율(%)과
검증 과정(근거)을 제시. NO-MOCK 원칙의 운영 도구.

### 5.2 검증 파트 · 방법론
| 파트 | 검증 대상 | 방법 | 합격 기준 |
|---|---|---|---|
| 히스토리 브리핑 | LLM 생성 기업 스토리 | `evaluate.py` 4-Phase: ①수치 정확성 ②인용 정합 ③RAGAS ④LLM Judge → overall_score·등급 | 평균 ≥ 75점(기존 77.1) |
| 주가/재무 | OHLCV·financials·financial_detail | **숫자 매칭**: DART 원본/공시 수치 ↔ DB 값 차이율, 합계 검증(자산=부채+자본) | 불일치 0건, 허용오차 0 |
| 밸류에이션 | 적정주가·WACC·멀티플 | 계산식 역검증(엔진 산출 JSON ↔ 화면), current_price 정합성 | 수식 재현 일치 |
| AI 챗봇 | RAG 답변 | **RAGAS**(faithfulness·answer relevancy) + 출처 페이지 존재 검증 | 근거 없는 답변 0 |
| 계열사 | 구조도/지분 | DART 원본 이미지 대비 노드/지분 일치 샘플 검수 | 시각 검수 통과 |

### 5.3 실행 모드
- **샘플 검증**: 무작위 N개(5~10) 즉시 검사 → 오류 항목·근거 하이라이트.
- **전수 검증**: 2,580종목 × 항목 배치(`healthcheck_full.py` 확장) → 오류율 리포트·CSV.
- 결과 누적: `data/validation_results/`(설계) → 추세 그래프.

### 5.4 화면 구성
- 파트별 오류율 게이지 + "검증 과정 보기"(어떤 값이 원본 어디와 대조됐는지).
- 실패 항목 테이블(종목·필드·DB값·원본값·차이).
- 재검증 버튼.

### 5.5 API 설계(spec)
| 경로 | 기능 |
|---|---|
| `POST /api/admin/verify/sample` | 파트·N개 샘플 검증 |
| `POST /api/admin/verify/full` | 전수 배치(비동기, 진행률) |
| `GET /api/admin/verify/report` | 최근 오류율·실패목록 |

## 6. (부가) 데이터 관리
- 사업보고서 갱신 시점(분기/연간 시즌) 캘린더 + 재적재 트리거 안내.
- 배치 잡 목록: OHLCV(일 16:00), 밸류 사전계산, Sankey 생성, 임베딩 적재.
- 재적재 실행은 **확인 모달** 후 스크립트 안내(직접 실행은 운영자 책임).

## 7. (부가) AWS 비용 관리
- S3(스토리지/요청), RDS(인스턴스·스토리지), EC2(메인+챗봇 GPU), CloudFront, NAT.
- 일/월 사용량·예상요금 카드(Cost Explorer API 연동, 설계).
- 임계 초과 경고(예: 월 $X 초과 시 배너).

## 8. 비기능 요구
- **읽기 우선**: 모니터링은 부하 낮은 COUNT/캐시. 무거운 전수검증은 비동기.
- **보안**: .env 시크릿 노출 금지, 관리자 경로 인증, 키 화면표시 금지.
- **정직성**: 데이터 없으면 "데이터 없음" 명시(추정/허위 금지).

## 9. 구현 우선순위(권장 단계)
1. **P0**: 탭1 헬스·DB현황·신선도·커버리지(읽기 전용) — 반나절.
2. **P1**: 탭2 샘플 신뢰도 검증(히스토리브리핑 evaluate.py 연결) — 1일.
3. **P2**: 전수 검증 배치 + 리포트 — 1일.
4. **P3**: 데이터관리·AWS 비용 — 0.5일.

## 10. 재사용 자산
- `healthcheck_full.py`(전수검수), 히스토리브리핑 `evaluate.py`/`merge_best.py`,
  `database/load_history_to_mongo.py`, `ohlcv_daily_sync.py`(배치 로그).
