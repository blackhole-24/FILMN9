FILMN9 — 주가·재무 파트 데이터 플로우

히스토리 브리핑 아래 모든 정보(주가차트·재무·공시·주주·경영인·밸류에이션)가 어디서 와서 어떻게 화면으로 나오는지 · 2026-06-01
전수 적재(정상) 일부 누락 거의 비어있음(문제) 실시간 외부호출(간헐적)

❓ "기업마다 정확히 나오게 하는 메인 파일 하나가 있나?" → 아니요.

  • 단일 프롬프트/설정 파일은 없습니다. 히스토리 브리핑처럼 "한 파일로 전 기업"이 아니라, 정보 블록마다 독립된 API 엔드포인트가 각자 다른 DB 테이블 또는 실시간 외부 API를 호출합니다.
  • 이걸 한 화면에 묶는 "오케스트레이터"는 프론트엔드 frontend/app/stock/[code]/page.tsx — 종목코드 하나로 15개를 동시에 fetch합니다.
  • 즉 "기업개요·주가·재무·공시는 각각 따로 작동"이 맞고, 정확도는 각 DB 테이블의 적재 커버리지에 달려 있습니다. 비어 보이는 건 그 테이블에 그 종목이 없기 때문.

← DB ohlcv 테이블
← yfinance/FDR (ohlcv_daily_sync·backfill_price)

상장 거의 전수 적재. 정지/신규 ~9개만 빈 차트 → 거래상태 배너로 대체.

💰 재무 하이라이트 23개뿐 ⚠

← DB financials 테이블 (요약 재무) — 23개 종목만 적재됨
🔴 핵심 문제: 랜덤 종목 대부분 여기서 빈칸. financial_detail(2,708)은 있으나 요약 테이블 미생성.

🔴 "랜덤 종목 빈칸" 원인 & 처방

  • 1. 재무 하이라이트 (최우선) — financials 테이블 23개뿐. → financial_detail(2,708)에서 매출·영업이익·순이익 요약을 추출해 financials 테이블 전수 생성하면 해결. (스크립트 1개로 가능)
  • 2. 밸류에이션 — valuations 테이블 0 + JSON 소수. → 6/3 밸류에이션 파트 SQLite 수령 후 전수 적재.
  • 3. 손익흐름도(Sankey) — 1,861개. → IS/CIS 없는 기업은 BS 기반 대체 또는 "데이터 없음" 안내.
  • 4. 재무정보 BS/IS — 2,708개. → 누락 ~160개(신규상장·미제출)은 거래상태/신규상장 안내로 대체.
  • 5. 전자공시·뉴스·실시간 — 외부 LIVE라 간헐적. → 자주 쓰는 건 DB 캐시 적재 검토(6/4 성능).
