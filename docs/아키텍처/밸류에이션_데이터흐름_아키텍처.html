2계산 엔진 내부 — Phase 1~7
화면 숫자가 만들어지는 실제 계산 순서 (run_valuation.py).
Phase 1-A
피어 베타 회귀 (Winsorize)
동종업계 비교기업들의 주가 수익률을 시장지수에 회귀 → 베타(β) 추정. 이상치는 winsorize로 보정.
→ peer_beta_result.json
Phase 1-B
XBRL 재무 추출 (4사 × 3년)
DART 전자공시 XBRL에서 대상기업+피어의 매출·영업이익·자산·부채를 추출 (캐시).
Phase 2
보통주 시가총액 E 산출
기준일 주가 × 발행주식수 → 자기자본 시장가치 E. (자본구조 가중치 계산용)
Phase 3
WACC — Hamada Unlever/Relever + Rf + 가중평균
피어 베타를 부채영향 제거(Unlever)→대상 자본구조로 재반영(Relever). Ke = Rf + β·ERP + SRP, Kd(세후), E/D 가중 → WACC.
→ wacc_result.json
Phase 4
DCF — FCFF 5년 Fade-out + Terminal Value
향후 5년 잉여현금흐름(FCFF)을 점감(fade-out) 추정 → WACC로 할인 → 영구가치(TV, g=2%) 합산 = 기업가치(EV).
→ fcff_result.json · dcf_result.json
Phase 5
EV → Equity Value → 주당 적정가
EV − 순부채 − 소수주주지분 + 비영업자산(NOA) = 자기자본가치 → ÷ 주식수 = 주당 적정가.
Phase 6
멀티플 역산 적정가
피어 PER·EV/EBITDA 중앙값을 대상 실적에 적용 → 상대가치 기반 적정가 (DCF 교차검증).
→ multiples_result.json
Phase 7
불확실성 — 시나리오 + 민감도 + 토네이도
Bear/Base/Bull 3시나리오, WACC×성장률(g) 민감도 매트릭스, 변수별 영향도 토네이도 차트.
→ uncertainty_result.json

5왜 지금은 "데이터 준비 중"이 뜨나?
백엔드는 종목 폴더 존재 여부로 분기합니다. 데모 3종목만 폴더가 있습니다.

✓ 폴더 있음 → 실데이터

아모레(090430)·삼성전기(009150)·NAVER(035420)는 data/valuation_results/에 JSON 6개가 있어 → 밸류 전체 화면 + "✓ 실데이터" 배지 표시.

✗ 폴더 없음 → 준비 중

나머지 ~2,580종목은 엔진을 아직 안 돌려 폴더가 없음 → API가 is_mock:true 반환 → 프론트가 "밸류에이션 데이터 준비 중" 표시.

왜 가짜값을 안 보여주나? — 예전 코드엔 모든 종목에 아모레 값을 그대로 박아 보여주는 하드코딩 Mock(MOCK_VAL)이 있었습니다. 이는 NO-MOCK 원칙 위반(틀린 숫자 = 할루시네이션)이라, 폴더가 없으면 가짜 대신 "데이터 준비 중"으로 정직하게 표기하도록 바꿨습니다. 즉 화면이 "줄어든" 게 아니라 거짓을 제거한 것입니다.
전 종목으로 확장하려면? — 밸류 엔진(run_valuation.py)을 종목별로 실행해 JSON 6개를 data/valuation_results/{코드}_{이름}/에 채우기만 하면, 서버 재시작 없이 해당 종목이 자동으로 실데이터로 전환됩니다(백엔드가 폴더를 매 요청마다 탐색).
