# 계열회사 시각화 작업 정리

이 문서는 DART 계열회사 시각화 작업을 이어가기 위한 인수인계용 정리입니다. 이 파일만 보고도 우리가 왜 이 방향을 잡았고, 어디까지 구현했고, 다음에 무엇을 해야 하는지 알 수 있게 작성했습니다.

## 0. 최신 상태

2026-06-02 기준으로 `전 종목 배치화`까지 구현했고, 실제 전체 실행도 완료했다.

이제 다음 명령으로 전체 종목 대상 계열회사 구조도 SVG 생성/원본 이미지 재사용 summary 생성이 가능하다.

배치 동작:

- DART 원본 이미지가 있는 기업은 `original_image_reused`로 summary에 기록하고 계열회사 구조도를 새로 만들지 않는다.
- 원본 이미지가 없는 기업은 `generated_structure_diagram`로 계열회사 구조도 SVG를 생성한다.
- 계열회사가 없으면 `no_affiliates`로 기록한다.

- 우선주/스팩은 기본 배치에서 제외하고 `excluded_security_type`으로 기록한다.
- 실패한 기업은 전체 실행을 멈추지 않고 `error`로 기록한다.
- 삼성전자/삼성물산/삼성전기/삼성SDI 등 삼성 주요 코드는 배치에서도 샘플 때 만든 `삼성그룹 핵심 교차지분` 로직을 사용한다.

## 1. 최종 목표

기업별 DART 사업보고서의 `계열회사 등에 관한 사항`을 시각화한다.

우리가 정한 방향은 다음과 같다.

1. DART에 KT처럼 이미 만들어진 `소유지분도/출자계통도 이미지`가 있는 기업은 그 원본 이미지를 우선 사용한다.
2. 원본 이미지가 없는 기업은 우리가 직접 `계열회사 구조도`를 생성한다.
3. 단순 계열회사 목록보다 `출자회사 -> 피출자회사 -> 지분율` 관계를 우선 보여준다.
4. 지분율이 없는 경우에도 계열 구조 자체는 보여준다.
5. 복잡한 관계는 전부 펼치지 않고 `기타 관계기업 N개`, `기타 비핵심 관계 N개`처럼 요약 노드로 접는다.

## 2. 핵심 판단

초기에는 모든 계열회사를 네트워크 그래프로 그리려 했지만, 삼성물산/삼성전자처럼 관계가 복잡한 기업은 선이 너무 많이 교차해서 보기 어려웠다.

그래서 최종 메인 시각화는 `계열회사 구조도`로 정했다.

형태는 다음과 같다.

- 왼쪽에 기준선 또는 그룹 기준 노드
- 기준선에서 오른쪽으로 출자회사 가지 분기
- 출자회사 오른쪽에 피출자회사 목록 표시
- 화살표 위에 지분율 표시
- 자회사 안의 자회사는 한 단계 더 오른쪽으로 확장
- 너무 많은 하위 관계는 요약 노드로 접기

NetworkX 결과물은 비교/실험용으로만 둔다. 발표나 서비스 메인 화면에는 `*_affiliate_structure.png` 또는 `*_affiliate_structure.svg`를 쓰는 것이 좋다.

## 4. 삼성 그룹 관련 핵심 개선

삼성전자/삼성물산의 경우 단순 자회사 목록보다 DART 표의 `출자회사 -> 피출자회사 -> 지분율`이 더 중요하다고 판단했다.

예를 들어 DART 표에는 다음 같은 관계가 있다.

- 삼성물산 -> 삼성바이오로직스 43.1%
- 삼성물산 -> 삼성에피스홀딩스 43.1%
- 삼성물산 -> 삼성생명보험 19.3%
- 삼성물산 -> 삼성전자 4.4%
- 삼성전자 -> 삼성디스플레이 84.8%
- 삼성전자 -> 삼성바이오로직스 31.2%
- 삼성전자 -> 삼성전기 23.7%
- 삼성전자 -> 삼성SDI 19.4%

기존에는 100% 하위/해외 자회사가 먼저 표시되어 이런 핵심 관계가 밀렸다. 그래서 `build_affiliate_structure_diagrams.py`에서 삼성 그룹 모드는 `핵심 교차 지분 관계`를 우선 표시하도록 수정했다.

현재 삼성 그룹 그래프의 방향:

- `삼성그룹`을 가상 루트로 둔다.
- 삼성전자, 삼성물산, 삼성생명보험, 삼성SDI, 삼성전기, 삼성화재해상보험, 삼성바이오로직스 등을 주요 출자회사로 둔다.
- 각 출자회사 아래에 핵심 피출자회사와 지분율을 표시한다.
- 기타 비핵심 관계는 `기타 비핵심 관계 N개`로 접는다.
- 조회 기업이 삼성물산이면 삼성물산 가지가 맨 위에 오도록 처리했다.

## 10. 다음에 해야 할 일

### 10.1 전체 종목 배치 실행

전체 실행:

```powershell
python scripts/build_affiliate_structure_diagrams.py --all
```

권장 옵션:

```powershell
python scripts/build_affiliate_structure_diagrams.py --all --limit 20
python scripts/build_affiliate_structure_diagrams.py --code 028260
python scripts/build_affiliate_structure_diagrams.py --code 030200
```

동작 방식:

1. `output/affiliate_visualization` 아래 종목 폴더를 순회한다.
2. 각 폴더에서 `affiliate_visual_data.json`을 읽는다.
3. `affiliate_visual_metadata.json`에서 `has_original_image`를 확인한다.
4. 원본 이미지가 있으면 계열회사 구조도를 만들지 않고 원본 이미지 경로를 summary에 기록한다.
5. 원본 이미지가 없고 edge/affiliate 데이터가 있으면 계열회사 구조도 SVG를 생성한다.
6. 계열회사가 없으면 `no_affiliates`로 기록한다.
7. 원천/파싱 데이터가 부족하면 `skipped_insufficient_data`로 기록한다.
8. 우선주/스팩은 기본적으로 `excluded_security_type`으로 기록하고 SVG를 만들지 않는다.
9. 실패한 종목은 전체 실행을 멈추지 말고 summary의 `errors`에 기록한다.

### 10.2 PNG 자동 변환 방식 결정

현재 SVG -> PNG 변환은 Chrome headless로 했다.

예시:

```powershell
$chrome = 'C:\Program Files\Google\Chrome\Application\chrome.exe'
$svgs = Get-ChildItem -LiteralPath '.\output\affiliate_structure_samples' -Recurse -Filter '*_affiliate_structure.svg'
foreach ($svg in $svgs) {
  $text = Get-Content -LiteralPath $svg.FullName -Raw
  $width = 1600
  $height = 1100
  if ($text -match 'width="([0-9]+)"') { $width = [int]$Matches[1] }
  if ($text -match 'height="([0-9]+)"') { $height = [int]$Matches[1] }
  $png = [System.IO.Path]::ChangeExtension($svg.FullName, '.png')
  $uri = [System.Uri]::new($svg.FullName).AbsoluteUri
  & $chrome --headless=new --disable-gpu --hide-scrollbars --screenshot=$png --window-size=$width,$height $uri | Out-Null
}
```

전체 배치에 PNG까지 포함할지, 서비스에서는 SVG만 쓰고 README/발표용 샘플만 PNG로 변환할지 결정해야 한다.

추천:

- 서비스/DB 저장용: SVG 경로 저장
- README/발표용 샘플: PNG 생성

## 11. 최종 방향 요약

최종 서비스 흐름은 다음이 가장 좋다.

```text
사용자가 기업 조회
  -> DB에서 해당 기업/기준연도 시각화 존재 여부 확인
  -> 있으면 저장된 원본 이미지 또는 계열회사 구조도 SVG 반환
  -> 없으면 DART/RAG 기반 데이터 확인
  -> 원본 이미지 있으면 원본 저장
  -> 원본 이미지 없으면 계열회사 구조도 생성
  -> 결과 파일과 edge 데이터를 DB에 저장
  -> 같은 날짜/같은 보고서 기준 요청은 저장본 재사용
```

전체 종목을 매번 다 생성하는 것보다, 발표/검증용으로 전체 배치를 한 번 돌리고 실제 서비스에서는 요청 기반 캐시 방식이 더 적합하다.

## 12. 다음 작업자가 가장 먼저 할 것

1. 현재 스크립트 문법 확인

```powershell
python -m py_compile scripts/build_affiliate_structure_diagrams.py
```

2. 문법 OK면 `--limit 5`부터 전체 배치 옵션 구현/검증

```powershell
python scripts/build_affiliate_structure_diagrams.py --all --limit 5
```

3. 생성 결과 중 다음을 확인

- 원본 이미지 기업은 건너뛰거나 원본 경로 기록되는지
- 원본 이미지 없는 기업은 계열회사 구조도 SVG가 생성되는지
- 지분율 색상 규칙이 유지되는지
- 너무 복잡한 기업에서 요약 노드가 생기는지
- summary JSON/CSV가 남는지

4. 이후 전체 실행

```powershell
python scripts/build_affiliate_structure_diagrams.py --all --redraw-original
```

5. 업로드 폴더에 필요한 파일만 복사

```text
계열회사시각화/scripts/
계열회사시각화/samples_structure_diagrams/
계열회사시각화/시각화_작업정리.md
계열회사시각화/README.md
```

## 13. 결론

현재 샘플 기준 `계열회사 구조도` 방향은 마무리해도 되는 수준이고, 전체 종목용 배치화도 구현 및 실행 완료되어 있다.

다음 작업은 `_summary.json`, `_summary.csv`를 DB에 적재하거나 서비스에서 읽는 방식으로 연결하는 것이다. 계열회사 없음 5개는 별도 안내 UI를 두고, 데이터 부족 257개는 원천/파싱 데이터 부족 안내로 분리하면 된다. 제외 11개는 우선주/스팩 제외 케이스로 처리하면 된다.

최종본으로 사용할 이미지는 `*_affiliate_structure.png/svg`이고, `networkx/sankey/graphviz`는 비교 실험용으로만 보면 된다.
