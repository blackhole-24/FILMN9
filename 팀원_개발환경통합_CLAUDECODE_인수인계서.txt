STEP 0-A. 기존 FILMN9 폴더 백업 (충돌 방지)
================================================================

  ① 본인 PC에 이미 FILMN9 관련 폴더가 있는지 사용자에게 확인 요청:

  사용자에게 질문 예시:
    "본인 PC에 이미 FILMN9 또는 filmn9 폴더가 있나요?
     있다면 어디 위치해 있나요? (예: C:\Users\<본인>\FILMN9)"

  ② 기존 폴더가 있다면, Bash 도구로 백업 (이름만 변경):

    Windows:
    > cd C:\Users\<본인>
    > Move-Item FILMN9 FILMN9_backup_20260526

    Mac/Linux:
    > cd ~/
    > mv FILMN9 FILMN9_backup_20260526

  ③ 백업 완료 후 사용자에게 보고:
    "기존 FILMN9 폴더를 FILMN9_backup_20260526 으로 이름 변경했습니다.
     이전 작업 내용은 보존되어 있으며, 환경 구축 완료 후 필요한 파일만
     골라서 새 FILMN9 폴더로 옮기실 수 있습니다."

  ⚠️ 절대 rm/Remove-Item으로 삭제하지 말 것. 반드시 백업.

STEP 2. data 패키지 zip 받기 + 압축 해제
================================================================

  ⚠️ GitHub에는 data/ 폴더가 .gitignore 되어 있어 데이터 파일이 없음.
     반드시 Google Drive에서 별도 다운로드 후 클론된 폴더에 풀어야 함.

  ① 사용자에게 Google Drive 링크 확인 요청:

  사용자에게 질문 예시:
    "Google Drive에서 FILMN9_DATA_* zip 파일을 다운받으셨나요?
     본인이 어떤 작업자인지 알려주세요:

     [A] 데모 시연/검증만: FILMN9_DATA_1_필수.zip (3.4 MB) 만 필요
     [B] RAG 작업자: 패키지 1 + FILMN9_DATA_2_RAG작업자.zip
     [C] 재수집 작업자: 패키지 1 + 패키지 3a, 3b
     [D] 모두 받음: 패키지 1, 2, 3 전부"

  ② 다운로드 위치 확인:
    보통 C:\Users\<본인>\Downloads\ 에 받았을 것임.

  ③ data 폴더 생성 (FILMN9 루트 안):
    Bash 도구로:
    Windows:
    > cd C:\Users\<본인>\FILMN9
    > mkdir data

    Mac/Linux:
    > mkdir ~/FILMN9/data

  ④ zip 압축 해제 (data 폴더 안에 풀기):

    Windows PowerShell:
    > Expand-Archive "C:\Users\<본인>\Downloads\FILMN9_DATA_1_필수.zip" -DestinationPath C:\Users\<본인>\FILMN9\data -Force

    Mac/Linux:
    > unzip ~/Downloads/FILMN9_DATA_1_필수.zip -d ~/FILMN9/data

    ※ 필수 zip은 내부에 data\filmn9.db, data\parsed_history\ 등이
      구조 그대로 들어있어 자동으로 올바른 위치에 풀림.

  ⑤ 압축 해제 검증:
    Glob 도구로 다음 경로에 파일 존재 확인:
    - C:\Users\<본인>\FILMN9\data\filmn9.db (5.7 MB)
    - C:\Users\<본인>\FILMN9\data\parsed_history\*.json (145개)
    - C:\Users\<본인>\FILMN9\data\corp_code_map.json

  ⑥ (RAG/재수집 작업자 한정) 추가 zip 풀기:
    Package 2 (RAG): FILMN9_DATA_2_RAG작업자.zip → data 안 zip 파일들
                     필요 시 각각 풀어야 함.
    Package 3 (재수집): FILMN9_DATA_3a_raw.zip 등을 data\raw 등으로 풀기.

STEP 3. .env 파일 생성 (사용자 입력 필수)
================================================================

  ⚠️ 보안상 .env는 GitHub에 커밋되지 않음.
     사용자가 직접 API 키를 입력해야 함.

  ① 템플릿 복사:
  Windows:
  > copy 개발환경_통합\.env.template .env

  Mac/Linux:
  > cp 개발환경_통합/.env.template .env

  ② 사용자에게 .env 파일 열어서 다음 키 입력 요청:

    [필수 키]
    - DART_API_KEY        (각자 발급: https://opendart.fss.or.kr/ 무료, 1분)
    - OPENAI_API_KEY      (팀 공용 — 이미 알고 있는 키 사용)
    - MONGO_URI           (★ 메인 개발자에게 슬랙 DM 1:1 요청 필요)
    - MONGO_DB=filmn9
    - MONGO_COLLECTION=histories

    [선택 키]
    - ECOS_API_KEY        (각자 발급: https://ecos.bok.or.kr/api/ 무료)

  ③ MongoDB URI 요청 메시지 템플릿 (사용자에게 안내):

    팀원 → 메인 개발자(기업개요 파트) 슬랙 DM 예시:
    "FILMN9 환경 구축 중입니다. .env 입력을 위해 MONGO_URI 부탁드립니다.
     입력 후 절대 GitHub 커밋하지 않겠습니다."

  ④ 입력 확인:
  > Grep "MONGO_URI" .env       # 값이 채워졌는지 확인

  ⑤ Git 무시 검증 (.env가 .gitignore에 등록되어 있는지):
  > git check-ignore -v .env
    → ".gitignore:151:.env  .env" 처럼 나와야 정상

  ※ MONGO_URI 비워두어도 진행 가능 (폴백 모드 동작 — STEP 7 참조)
    단, MongoDB 적재된 2,526개 종목 히스토리는 사용 불가.

STEP 6. SQLite DB 검증 (zip에 포함 — init 불필요)
================================================================

  ⚠️ STEP 2에서 FILMN9_DATA_1_필수.zip 을 풀었으면
     data/filmn9.db (5.7 MB) 가 이미 존재해야 함.

  ① DB 파일 검증:
  > Glob data/filmn9.db

  파일이 없으면 → STEP 2 다시 진행 (사용자에게 zip 다운로드 재확인 요청)

  ② 최후 수단 (zip 못 받았을 때만):
  > python db/init_db.py
  > python db/batch_demo3.py
  (DART API 키 필요, 30초~수분 소요)

  ③ 스키마 검증:
  > python check_full_schema.py

  출력에 9개 테이블 모두 보여야 함:
    - company_info
    - financials
    - financial_detail
    - ohlcv
    - shareholders
    - executives
    - disclosures
    - credit_ratings
    - valuations

[자주 발생하는 문제 & 해결]
================================================================

Q1. "ModuleNotFoundError: No module named 'fastapi'"
    A. venv 활성화 안 됨. STEP 4-② 다시 수행.

Q2. "npm ERR! ENOENT package.json"
    A. frontend/ 폴더에 있는지 확인. cd frontend 필수.

Q3. "filmn9.db: no such table"
    A. STEP 6 다시 수행. init_db.py → batch_demo3.py 순서.

Q4. MongoDB TLSV1_ALERT 에러
    A. 폴백 모드로 진행. STEP 7 분기 처리 참조.
       자세한 해결은 기업개요 파트_MongoDB_환경구축_가이드.md 참조.

Q5. 포트 충돌 (3000 or 8000 already in use)
    A. Windows: netstat -ano | findstr ":3000"
       찾은 PID 종료: taskkill /PID <pid> /F
       Mac/Linux: lsof -i :3000 → kill -9 <pid>

Q6. CORS 에러 (브라우저 콘솔)
    A. api/main.py 의 CORS 설정 확인.
       localhost:3000 이 allow_origins 에 포함되어야 함.

Q7. 한글 깨짐 (Windows PowerShell)
    A. chcp 65001 실행 → UTF-8 모드 전환.
       또는 git config --global core.quotepath false
