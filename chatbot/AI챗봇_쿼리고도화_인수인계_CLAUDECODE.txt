    답변: "제공된 보고서에서 해당 정보를 찾을 수 없습니다."  ← 실패

  - 사용자가 원하는 답(찰떡 답변):
    "삼성전자 2026년 1분기 — 매출 OOO조, 영업이익 OOO조, 당기순이익 OOO조
     (가능하면 전분기/전년동기 대비 QoQ·YoY 비교까지)"

  - 핵심: 시연 때 어떤 질문이 나올지 예측 불가. "어떤 질문에도 근거 있는 정답"이 목표.

2. 원인 진단 (2가지 근본 원인)
────────────────────────────────────────────────────────────────────────────────
  원인 A) 데이터 커버리지 부족
    - 현재 벡터DB(ChromaDB, 청크 1,922,942개)는 대부분 "2025 사업보고서(연간)" 기반.
    - "2026년 1분기 분기보고서"가 임베딩 안 돼 있으면 검색 자체가 불가 → 질의 문제 아님.

  원인 B) 숫자 질문은 텍스트-RAG가 원래 약함
    - "실적 = 매출/영업이익/당기순이익"은 보고서 문장 검색보다,
      이미 보유한 "정형 DB"에서 숫자를 뽑는 것이 훨씬 정확하고 계산(QoQ/YoY)도 가능.
    - 정형 DB 위치(SQLite filmn9.db): financials, financial_detail 테이블 (백엔드가 이미 서빙).

  ★ 핵심 통찰: "찰떡 답변"의 정답은 'RAG를 더 똑똑하게'가 아니라
    "질문 종류에 따라 RAG(글 설명) vs 정형DB(숫자)로 경로를 나눠 보내는 것(라우팅/Agentic RAG)".
    그리고 이 방향은 돈이 거의 안 든다(우리 DB·로컬 GPU·기존 OpenAI 키 사용).

5. 추천 실행 순서 (가성비 로드맵) — 그 실패 질문을 가장 빨리 고치는 조합

  STEP 2) #1 숫자→DB 라우팅 (1~2일) → "실적" 질문 정확 해결 (가장 큰 임팩트)
  STEP 3) #4 분기보고서 데이터 보강 (1~2일) → "2026 1분기" 질문 가능
  STEP 4) #3 하이브리드 검색 (1~2일) → 검색 정확도 +17%↑
  STEP 5) #8 평가셋 (병행) → 개선을 숫자로 증명(데모 신뢰성)
  STEP 6) #5·#6·#7 사이사이 튜닝
  ※ 그 실패질문("삼성전자 1분기 실적")의 핵심 해법 = #1 + #2 + #4 조합.

    - 모든 수치/문장은 출처(DART·DB·명시적 계산식) 근거 필수.

7. 착수 가이드 (Claude Code가 바로 할 일)
────────────────────────────────────────────────────────────────────────────────
  (0) 서버 띄우고 현재 동작 확인:
      - 위 [챗봇 서버 기동]으로 8800 기동 → /health 에서 total_chunks·cuda 확인.
      - 실패 재현: POST /chat {"message":"삼성전자 2026 1분기 실적","ticker":"005930"}
        (한글은 UTF-8로 — curl 대신 python requests 권장. 셸 인코딩 깨짐 주의.)

  (1) STEP 1 (#2 온톨로지): ontology_b.json 에 "실적/재무수치" 개념과 트리거·확장어 추가.
      예) trigger:["실적","성과","재무"] → expand:["매출액","영업이익","당기순이익","영업수익"]
      ontology_b.py 의 analyze() 가 이를 검색쿼리에 반영하는지 확인.

  (2) STEP 2 (#1 라우팅): query_analyzer 의 intent가 재무수치형이면(예 intent=="재무수치"),
      pipeline 에서 RAG 대신 백엔드 정형DB(financials/financial_detail) 조회로 분기.
      - 데이터 출처(연도·분기·단위) 명시 + QoQ/YoY는 DB의 다년치로 계산해 인용.
      - 숫자 없으면 "해당 분기 데이터 없음"으로 정직 표기(절대 추정·생성 금지).

  (3) STEP 3 (#4 데이터): 2026 분기보고서가 DB에 있는지 먼저 점검(메타 report_kind 등).
      없으면 phaseA_collect→phaseB_embed 로 분기보고서 추가 임베딩(로컬 GPU).

  (4) 각 단계 후 (0)의 실패질문으로 회귀 테스트 + #8 골든질문셋으로 정확도 측정.
